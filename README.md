# tammaroterracciano.github.io

Personal academic website of Tammaro Terracciano, Assistant Professor of Finance at IESE Business School.

Live at <https://tammaroterracciano.github.io>.

Plain HTML and CSS. No framework, no build step, no JavaScript, and no third-party requests: every asset, including the font, is served from this repository. GitHub Pages serves the files in this repository exactly as they are, from the `main` branch. Committing a change publishes it, usually within a minute.

## How to edit

### In the browser (simplest)

1. Open the file on GitHub, for example `index.html`.
2. Click the pencil icon, top right.
3. Make the change. Cmd+F searches within the file.
4. Click **Commit changes**.

The live site updates about a minute later.

### Locally

Clone the repository and edit in any plain-text editor. To preview before committing, serve the folder over HTTP rather than opening the file directly, so page-to-page links and the CV link behave as they will in production:

```
python3 -m http.server 8765
```

Then open <http://localhost:8765/index.html>.

Do not edit these files in a rich-text editor such as TextEdit in its default mode. It will corrupt them.

## Common tasks

### Update the CV

Replace `assets/Terracciano_CV.pdf`, keeping the filename. Nothing else changes.

### Add a paper

Copy an existing `<div class="paper">` block in `index.html` and edit it. Full shape:

```html
<div class="paper">
  <p class="title"><a href="LINK">Paper Title</a><span class="status">Submitted</span></p>
  <p class="meta">with A. Coauthor (Institution). 2026.</p>
  <p class="meta">Working Paper No. 123</p>
  <div class="tags"><a href="LINK">SSRN</a><details class="abs">
      <summary>Abstract</summary>
      <p>Abstract text.</p>
      </details></div>
</div>
```

Only the title is required.

- Omit `<span class="status">` when there is no status. The separating dot is generated by CSS, so never type one.
- Omit the `<a>` around the title when there is no public link.
- Use as many `<p class="meta">` lines as needed, or none.
- Put additional links inside `<div class="tags">`, before the `<details>`.
- Omit the whole `<details>` block when there is no abstract.

Papers render in source order.

### Add a media mention, op-ed, or policy item

Copy a neighbouring `<li>` in `outreach.html`:

```html
<li><a href="LINK">Headline</a>, by Author <span class="venue">&middot; <b>Outlet</b>, 12 Mar 2026</span></li>
```

Omit the `<a>` when there is no link. Italian articles live inside the collapsible `<details class="more">` block at the end of the page.

### Change the bio

`index.html`, inside `<div class="bio">`. One `<p>` per paragraph.

### Change the name or job title in the top bar

Present in **both** HTML files. Edit both or the pages will disagree:

```html
<span class="bname">Tammaro Terracciano</span>
<span class="btitle">Assistant Professor of Finance</span>
```

### Change colors

The `:root` block at the top of `style.css`:

```css
--blue:  #14477d;   /* links, paper titles */
--green: #1f5132;   /* small accents */
--text:  #1b201c;   /* body text, status labels */
--muted: #61695f;   /* secondary text */
--bg:    #f7f7f4;   /* page background */
--maxw:  1020px;    /* shared content width of both pages */
```

Two further blocks below redefine these for dark mode. **Change all of them**, or dark mode breaks.

### Change the font

The site uses one typeface, Source Serif 4, **self-hosted** from `assets/fonts/`. It is not loaded from Google Fonts, and must not be: see Privacy below.

The family is named in `style.css`:

```css
--serif: "Source Serif 4", Georgia, "Times New Roman", serif;
```

and the file itself is declared by the `@font-face` block at the very top of `style.css`. One variable file covers every weight the site uses (400, 500, 600, 700), so there is nothing to add when you start using a new weight in that range.

To swap in a different typeface:

1. Put the new `.woff2` in `assets/fonts/`, with its licence file.
2. Point the `src:` in the `@font-face` block at it and set `font-family` to the new name.
3. Update `--serif` in `:root` to match.
4. Check the `unicode-range` still covers the characters the site uses. The current value is Google's standard Latin subset, which covers English plus the accents in the Italian titles.

There is no `<link>` tag to edit. The HTML files reference no fonts at all.

## Privacy

The site sets no cookies, runs no analytics, and contacts no third party. Both pages carry this line in the footer:

> This site sets no cookies, runs no analytics, and makes no third-party requests &mdash; nothing about your visit is collected.

**That statement has to stay true.** Before adding anything, check it does not break it:

- **No remote fonts.** The font is self-hosted precisely for this reason. Loading it from Google Fonts sends every visitor's IP address to Google on every page view; an earlier version of this site did that.
- **No CDNs.** Do not pull CSS, JavaScript, or icons from jsdelivr, unpkg, cdnjs or similar. Copy the file into `assets/` instead.
- **No analytics**, including the privacy-branded ones. They still make third-party requests.
- **No embeds** &mdash; YouTube, X, Google Maps, Disqus. They set cookies and phone home.
- **Ordinary hyperlinks are fine.** Linking to SSRN or Il Sole 24 Ore costs the visitor nothing until they click it.

There is no cookie banner because there are no cookies to consent to. If any of the above ever changes, update the footer line on **both** pages to match. An inaccurate privacy claim is worse than no claim.

## Design conventions

Keep these when making changes, or the two pages stop matching.

- **One typeface** across the whole site. `--sans` is a legacy alias pointing at `--serif`; do not reintroduce a second family.
- **Both pages share `--maxw`.** They must stay the same width.
- **Blue** carries links, the Abstract toggles, and paper titles (bold 700). **Black bold** carries paper statuses and publication venues. **Grey** carries secondary detail.
- **Paper statuses are plain text**, not badges. The `·` before them comes from `.paper .status::before`.
- **The email address is deliberately not a `mailto:` link**, anywhere, including both footers. It is `<span class="email">`.
- **Abstracts** use native `<details>`. They sit inline in the `.tags` row, justified above 560px wide and ragged-right below.
- **`index.html` carries a visually hidden `<h1>`** (`.sr-only`) because the visible name lives in the navigation bar. Keep it for screen readers and search engines.
- **Light and dark mode are both supported** via `prefers-color-scheme`. Check any color change in both.
- **Breakpoints** are 720px (hero stacks), 560px (abstracts stop justifying) and 430px (job title hides in the top bar).
- `<body class="outreach">` is an unused hook kept for page-specific styling.
- **The footer privacy line sits on both pages** and must stay accurate. See Privacy above.
- **Everything the browser loads comes from this repository.** No remote fonts, CDNs, analytics or embeds.

## Notes for AI assistants

If you are Claude, Codex, or another agent asked to modify this site, follow these rules.

**Scope and stack**

- Static HTML and CSS only. Do not add a build step, framework, bundler, package manager, or site generator. Do not add JavaScript unless explicitly asked.
- **Do not introduce a third-party request.** No remote fonts, CDN links, analytics or embeds; vendor any new asset into `assets/`. Read the Privacy section first: the footer claims the site makes none, and that claim must remain true.
- All asset paths are relative. Keep them relative so the site works at any address.
- `index.html`, `style.css` and the `assets/` folder must keep their names and locations. GitHub Pages depends on `index.html` at the repository root.

**Content accuracy**

- Never invent, paraphrase, or reconstruct an abstract, title, co-author, venue, date, or publication status. Take them from a source the user supplies or from a page you have actually read, and say which.
- SSRN blocks automated fetching. Do not rely on it for abstracts.
- Verify a URL resolves before adding it.

**Consistency**

- Read the Design conventions above before restyling anything. A change to one page usually needs the matching change to the other.
- Any color change must be made in the light block and both dark blocks.
- Check the result at desktop width, around 560px, and at 375px. Confirm no horizontal overflow.
- Keep text contrast at or above 4.5:1 against its background in both themes.

**Editing**

- Prefer editing `style.css` over adding inline `style` attributes, except for genuine one-offs.
- Preserve the exact `<details class="abs">` structure inside `.tags`; the closing `</details></div>` must stay adjacent.
- HTML ignores blank lines. Use CSS margins for spacing.

**Publishing**

- This repository is public. Do not commit local filesystem paths, private URLs, credentials, or personal data beyond what is already published.
- Committing to `main` publishes immediately. Do not commit speculative or half-finished work.
